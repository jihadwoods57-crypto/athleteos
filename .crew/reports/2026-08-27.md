  the backlog's top security item has been: a minor can edit their own age and flip off

  photo sync, the adults-only marketplace. I proved it first (the item said "verify
  first"): built a full copy of the production database schema on this machine, signed in
  as a 15-year-old, and two ordinary saves later the system believed they were 25. The fix
  makes age the server's decision: the app can no longer write the age fields directly,
  and birth dates go through one server door that refuses to turn a known minor into an
  adult. A kid can still correct their birth date to another under-18 date, an adult can
  still fix a typo, and signup works exactly as before — but the one edit that removes a
  child's protections now needs a parent or support. Under-13 dates are refused by the
  server too (they were only ever blocked by the app's own forms). The profile screen now
  says plainly why a save was refused instead of blaming the connection. Proof: 18 new
  authorization checks covering the attack and every legitimate path, 565/565 checks
  green, all 7 SQL suites green, all 12 build gates green, app bundle rebuilt with exactly
  the two changed files. NOT live yet: applying it needs the database credential — the
  exact steps (update first, then the database change) are written into the backlog so
  it's a five-minute job for the first session with keys.
